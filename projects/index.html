01 / STANDARDS REVIEW

CDASH

A Python-based review pilot that compares study data dictionaries with supplied CDASH references and terminology, then presents traceable differences and reviewer questions.

ROLE Designer / Developer / ReviewerTOOLS Python · CDASH · SDTM readinessSTATUS Review pilot

REVIEW QUESTIONDoes the response set align with the supplied non-extensible terminology?Human decision required
THE PROBLEM

Manual standards review is repetitive and hard to trace field by field.

A reviewer needs to compare study definitions, standards context and terminology without losing where a finding came from.

THE DESIGN DECISION

Generate questions, not regulatory verdicts.

The workflow separates vendor-specific input from review logic, retains evidence and reports checks that cannot run instead of treating silence as a pass.

THE CONTROL

Keep human judgment in the loop.

Domain mappings are proposed, unmatched concepts remain in a review queue, and nothing is written back to the study dictionary automatically.

Standards-aware system thinking, evidence traceability, cautious automation design and the ability to translate a complex review process into a usable workflow.

THE PROBLEM

Flat exports hide participant-level patterns.

Repeated AM/PM events and multiple data streams are difficult to assess when each source is reviewed independently.

THE APPROACH

Normalize first, then create review views.

Event-level data is structured into participant timelines, compliance summaries, reconciliation views and a persistent issues log.

THE PRINCIPLE

Compliance and reconciliation are not the same signal.

The design keeps operational compliance separate from supporting evidence so a reviewer can understand what each data stream actually proves.

WHAT THIS DEMONSTRATES

Clinical-data modeling, operational oversight, multi-source reasoning and translating complex repeated events into reviewable study signals.

THE PROBLEM

Matching values does not always mean matching records.

Identifiers, visit labels, expected-record context and collection timing can differ across EDC and external transfers.

THE DECISION

Resolve identity and context before comparing fields.

The pipeline establishes participant/visit context, compares selected fields and preserves discrepancies as explicit review items.

THE CONTROL

Exceptions stay visible until reviewed.

A mismatch is not automatically corrected. The workflow preserves both source values and the context needed for a documented decision.

WHAT THIS DEMONSTRATES

External-data reconciliation, defensible exception handling, source preservation and quality-focused automation.

WHY EXCEL / VBA

Meet operational teams where the data already lives.

Controlled formulas and macros can remove repetitive handling without forcing a new platform into a simple workflow.

WHY PYTHON

Scale when repeated datasets outgrow manual review.

Configuration-driven processing is useful for repeated reconciliation, validation and standardized outputs.

GOVERNANCE

Automation still needs evidence.

Inputs, assumptions, rules, outputs and exceptions should be understandable to another reviewer, not only the developer.

WHAT THIS DEMONSTRATES

Pragmatic technical judgment: choosing the simplest appropriate tool while keeping clinical review, traceability and maintainability central.
